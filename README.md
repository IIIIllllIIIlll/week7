# 7주차 실습과제 — 파이프와 FIFO

7주차 실습 내용인 **파이프(`pipe`)를 이용한 부모-자식 통신**, **`dup2`를 이용한 명령 이어 붙이기**, **FIFO(`mkfifo`)를 이용한 프로세스 간 통신**을 구현한 저장소입니다.

## 1. 프로젝트 설명

수업 시간에 다룬 기본 예제 코드(`1_pipe_basic.c`, `2_pipe_dup2.c`, `3_fifo_read.c`, `4_fifo_write.c`)를 바탕으로 아래 3가지 과제를 구현했습니다.

| 파일명 | 역할 요약 | 주요 시스템 콜 / 함수 |
| :--- | :--- | :--- |
| `1_pipe.c` | 부모가 보낸 문자열을 자식이 대문자로 바꿔 돌려줌 (파이프 2개 왕복) | `pipe`, `fork`, `read`, `write`, `close`, `wait`, `toupper` |
| `2_pipeline.c` | `:`로 구분된 두 명령을 `dup2`와 `execvp`로 이어 붙임 | `pipe`, `fork`, `dup2`, `execvp`, `waitpid` |
| `3_fifo_read.c` | FIFO를 만들어 메시지를 먼저 기다려 받고 확인 답장 후 `unlink` 삭제 | `mkfifo`, `open`, `read`, `write`, `unlink` |
| `4_fifo_write.c` | 받는 쪽이 연 FIFO로 메시지를 보내고 확인 답장을 받음 | `open`, `write`, `read`, `close` |
| `Makefile` | 전체 컴파일(`make`), 테스트(`make test`), 정리(`make clean`) | `gcc -Wall -Wextra -O2` |

### 1) 파이프로 왕복 (`1_pipe.c`)
- **동작**: `./1_pipe "hello world"` 형태로 실행하면 부모 프로세스가 자식 프로세스에게 문자열을 보내고, 자식은 이를 대문자로 변환(`toupper`)하여 다시 부모에게 돌려줍니다.
- **핵심 원리**:
  - 파이프는 단방향이라 데이터를 주고받기 위해 부모→자식용(`p2c[2]`), 자식→부모용(`c2p[2]`) 파이프 2개를 만들었습니다.
  - 각 프로세스에서 쓰지 않는 파이프 끝을 바로 닫아 주어야 상대방 `read()`가 `EOF(0)`를 만나 정상적으로 다음 단계로 넘어갑니다.

### 2) `dup2`로 명령 이어 붙이기 (`2_pipeline.c`)
- **동작**: `./2_pipeline ls -l : wc -l` 처럼 `:`를 기준으로 두 명령어를 입력받아, 앞 명령의 출력을 뒤 명령의 입력으로 연결합니다.
- **핵심 원리**:
  - 명령행 인자(`argv`)에서 `":"` 위치를 찾아 `NULL`로 바꾼 뒤, 앞부분(`cmd1`)과 뒷부분(`cmd2`)을 각각 `execvp()`에 넘겨 실행합니다.
  - 첫 번째 자식은 표준출력(`STDOUT_FILENO`)을 파이프 쓰기 끝(`fd[1]`)으로, 두 번째 자식은 표준입력(`STDIN_FILENO`)을 파이프 읽기 끝(`fd[0]`)으로 `dup2()`를 통해 바꿔치기합니다.
  - 부모 프로세스는 파이프의 양쪽 끝(`fd[0]`, `fd[1]`)을 모두 닫아야 뒤 명령(`wc -l`)이 `EOF`를 보고 끝납니다.

### 3) FIFO로 메시지 주고받기 (`3_fifo_read.c`, `4_fifo_write.c`)
- **동작**: 터미널 두 개를 열어 받는 쪽(`./3_fifo_read`)을 먼저 실행해 두고, 다른 터미널에서 보내는 쪽(`./4_fifo_write "메시지"`)을 실행해 남남인 두 프로세스끼리 메시지를 주고받습니다.
- **핵심 원리**:
  - 파일 시스템 경로(`/tmp/sysprog_fifo`)에 이름을 가진 파이프(FIFO)를 생성해 부모-자식 관계가 아닌 프로세스끼리 통신합니다.
  - 받는 쪽의 `open()`은 보내는 쪽이 반대편을 열어 줄 때까지 기다립니다(블록).
  - 기존 예제에서 한 걸음 더 나아가 받는 쪽이 메시지를 받은 뒤 응답용 FIFO(`/tmp/sysprog_fifo_reply`)로 수신 확인(ACK) 답장을 돌려주도록 변형했으며, 통신이 끝나면 `unlink()`로 생성했던 FIFO 파일을 지웁니다.

## 2. 컴파일 및 실행 방법

    # 전체 컴파일
    make

    # 1번 과제 실행
    ./1_pipe "hello world"

    # 2번 과제 실행
    ./2_pipeline ls -l : wc -l

    # 3번 과제 실행 (터미널 2개 사용)
    ./3_fifo_read                        # 터미널 1 (먼저 실행)
    ./4_fifo_write "안녕하세요 반갑습니다"   # 터미널 2 (나중에 실행)

- **사용 계기 및 역할 분담**: 새로 출시된 AI 모델(아르곤 / Gemini)의 실제 성능이 어느 정도인지 궁금하여, 성능을 직접 테스트해 볼 겸 이번 과제에서 AI의 도움을 크게 받았습니다.
- **진행 방식**:
  - 저는 수업 시간에 학습한 강의 PPT 내용과 교수님께서 제공해 주신 예제 파일 12개(C, Go, Rust 버전)를 AI에 함께 제공하고, 과제 요구사항(파이프 2개 왕복, `:` 구분자 파싱 및 `dup2` 연결, FIFO 블로킹 확인 및 `unlink` 삭제)의 구현 방향성을 지시했습니다.
  - 실제 C 소스 코드 작성(`1_pipe.c`, `2_pipeline.c`, `3_fifo_read.c`, `4_fifo_write.c`)과 빌드 편의를 위한 `Makefile`, 그리고 **현재 읽고 계신 이 `README.md` 문서의 작성까지 모두 AI의 도움을 받아 완성**했습니다.

### 본인의 보강 및 확인 내용
1. **강의 예제 스타일 유지 및 핵심 제약조건 지시**
   - 단순히 정답 코드만 생성하게 하지 않고, 수업 자료의 주석 스타일(`[핵심 개념]`, `[컴파일·실행]`)과 `gcc -Wall -Wextra` 경고 없음 조건, 자식 프로세스에서의 `fflush(stdout)` 후 `_exit()` 호출 등 수업 PPT에서 강조된 시스템 프로그래밍 규칙이 코드에 그대로 반영되도록 프롬프트로 방향을 잡았습니다.
2. **과제 3번(`3_fifo_read.c` / `4_fifo_write.c`)의 양방향 응답 변형**
   - 기존 강의 예제는 이미 단방향 송수신이 구현되어 있어 그대로 내면 변형 과제의 의미가 약하다고 판단했습니다. 이에 따라 받는 쪽에서 몇 바이트를 받았는지 확인 답장(ACK)을 보내는 쪽으로 다시 돌려주고 두 FIFO를 모두 `unlink`로 삭제하는 구조로 변형했습니다.
3. **WSL Ubuntu + VS Code 환경 구축 및 직접 실행 검증**
   - AI가 작성해 준 코드를 로컬 Windows의 VS Code와 WSL(Ubuntu) 환경으로 가져와 직접 컴파일하고, 단일 터미널 및 분할 터미널 환경에서 파이프 EOF 처리와 FIFO의 `open()` 대기 동작이 강의 내용대로 정상 작동하는지 확인하며 실행 화면을 캡쳐했습니다.
